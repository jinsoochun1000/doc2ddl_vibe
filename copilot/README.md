# 이력서 데이터베이스 스키마

`../이력서.docx`에서 확인되는 이력서 항목을 Oracle 데이터베이스에 저장하기 위한 스키마와 예시 적재 SQL입니다.

## 파일

- `schema.sql`: Oracle 테이블, 제약조건, 인덱스 및 설명을 생성합니다.
- `seed.sql`: 원본 문서에 기재된 학력·경력·기술·프로젝트 값을 예시 데이터로 적재합니다.

## 테이블 구성

| 테이블 | 저장 내용 |
| --- | --- |
| `RESUME_PROFILE` | 이름, 생년월일, 연락처, 주소 및 기본 인적사항 |
| `RESUME_EDUCATION` | 학교, 전공, 재학 기간, 졸업 상태 |
| `RESUME_CAREER` | 회사, 근무 기간, 직위, 담당 업무 |
| `RESUME_SKILL` | 기술명과 A/B/C 숙련도 |
| `RESUME_CERTIFICATE` | 자격증명과 취득일 |
| `RESUME_TRAINING` | 교육명, 기간, 기관 |
| `RESUME_PROJECT` | 프로젝트, 기간, 고객사, 역할, 수행 업무, 개발 환경 |
| `RESUME_PROJECT_TOOL` | 프로젝트별 사용 도구 |

모든 상세 이력은 `RESUME_ID`로 기본 인적사항에 연결됩니다. 프로젝트 도구는 별도 테이블에 저장하며, 기간 유효성·숙련도·현재 재직 여부에 제약조건을 적용했습니다.

## 실행 순서

Oracle 12c 이상에서 대상 스키마로 접속한 뒤 다음 순서로 실행합니다.

1. `schema.sql`
2. `seed.sql` (문서의 예시 값을 적재할 경우)

DDL에는 기존 테이블을 삭제하는 구문이 없으므로, 동일한 스키마에 이미 같은 테이블이 있으면 생성이 실패합니다. `seed.sql`은 새로 만든 빈 테이블을 대상으로 한 예시이며, 기본 키를 명시하므로 동일한 데이터의 중복 실행은 피해야 합니다.

## 원본 데이터 유의사항

- 이름·학교·회사 등의 `홍길동`, `OOO` 표기는 원본 문서에 보이는 그대로 적재했습니다. 실제 값을 추정하거나 복원하지 않았습니다.
- 생년월일의 `YYYY-MM-DD`는 날짜가 아닌 서식 예시이므로 `NULL`로 두었습니다. 비어 있거나 `-`로 표시된 연락처 등도 미기재 값으로 취급했습니다.
- 원본에서 확인된 학력 2건, 경력 3건, 기술 3건, 프로젝트 3건을 적재합니다. 마지막 경력은 재직 중으로 표시되어 종료일을 `NULL`로 저장합니다.
- 자격증과 교육 항목에는 기재된 데이터 행이 없어 seed 데이터가 없습니다. 해당 항목을 입력할 수 있도록 테이블은 생성합니다.
- 사용 기술의 숙련도는 원본의 A/B/C 표기를 보존합니다. 프로젝트 수행 기간과 일자는 원문 표기를 날짜 값으로 변환했습니다.
