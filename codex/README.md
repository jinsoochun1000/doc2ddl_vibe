# 이력서 Oracle DB 설계

`../이력서.docx`의 개인 이력 카드와 SKILL INVENTORY를 8개 테이블로 구성했습니다. DDL, 원문 데이터 적재 SQL, 적재 결과 점검 SQL을 제공합니다. 대상은 Oracle Database 19c이며 IDENTITY를 사용하므로 12c 이상이 필요합니다.

## 파일 및 실행

| 파일 | 용도 |
| --- | --- |
| `01_schema.sql` | 테이블, PK/FK/UNIQUE/CHECK, 인덱스, 테이블·컬럼 한글 주석 생성 |
| `02_data.sql` | 원문 데이터 18행 적재, 성공 시 COMMIT |
| `03_verify.sql` | 원문별 건수·NULL 처리·재직중 상태 확인 및 프로젝트 조회 |

기존 동명 테이블이 없는 Oracle 사용자 스키마에 접속하여 파일 순서대로 실행합니다. 스키마 생성만 필요하면 첫 번째 파일만 실행합니다. 사용자 또는 데이터베이스 자체를 생성하는 스크립트는 아닙니다.

```sql
-- SQL*Plus / SQLcl: 이 파일들이 있는 디렉터리에서 실행
@01_schema.sql
@02_data.sql
@03_verify.sql
```

SQL Developer에서는 각 파일을 열고 **스크립트 실행(F5)**으로 실행합니다. PL/SQL 블록 뒤의 `/`는 유지해야 합니다. 접속 계정은 `CREATE TABLE`, `CREATE SEQUENCE` 권한과 테이블스페이스 quota가 필요합니다. 파일은 UTF-8이며, 한글을 저장할 수 있는 DB 문자셋(예: AL32UTF8)과 클라이언트 인코딩을 사용합니다.

DDL은 자동 커밋되므로 중간 오류 발생 시 앞서 생성된 객체는 남습니다. 스키마 스크립트는 1회 실행용이며 DROP이나 자동 초기화를 포함하지 않습니다. 적재 스크립트는 전용 세션에서 단독 실행하며, 실패 시 적재 트랜잭션을 롤백합니다. 같은 `source_file`이 있으면 재적재를 거부하지만, 이는 순차 실행 확인이며 동시 적재 잠금을 제공하지 않습니다. 원본명을 전역 UNIQUE로 제한하지 않아 향후 별도 문서·버전 관리 정책을 적용할 수 있습니다.

## 테이블 요약

| 테이블 | 원문 항목 및 주요 컬럼 | 적재 행 수 |
| --- | --- | ---: |
| `RESUME` | 성명, 생년월일, 성별, 소속회사, 입사일자, 부서, 직위, 병적, 전화, 이메일, 주소, 작성자, 기타 기술 | 1 |
| `RESUME_EDUCATION` | 학교, 전공/계열, 입학일, 졸업일, 졸업 상태 | 2 |
| `RESUME_CERTIFICATE` | 자격증명, 취득일 | 0 |
| `RESUME_CAREER` | 회사, 시작일/종료일, 재직중 여부, 직위, 담당업무 | 3 |
| `RESUME_TRAINING` | 교육명, 시작일/종료일, 기관 | 0 |
| `RESUME_SKILL` | 보유기술·외국어, 분류, 숙련도 A/B/C | 3 |
| `RESUME_PROJECT` | 프로젝트명, 참여기간, 고객사, 근무회사, 역할, 수행업무 | 3 |
| `RESUME_PROJECT_ENV` | 프로젝트별 기종·OS·언어·DBMS·TOOL·통신·WAS 값 | 6 |

`RESUME`은 한 이력서의 기본정보이며, 학력·자격증·경력·교육·보유능력·프로젝트와 각각 1:N 관계입니다. `RESUME_PROJECT`와 `RESUME_PROJECT_ENV`도 1:N 관계입니다. 이 설계는 문서별 내용을 보관하며, 동일인의 여러 이력서를 통합하는 인물 마스터는 두지 않았습니다.

## 변환 및 무결성 규칙

- PK는 `NUMBER GENERATED ALWAYS AS IDENTITY`입니다. 적재 시 `RETURNING ... INTO`로 생성 키를 연결하므로 ID가 1부터 시작한다고 가정하지 않습니다.
- 한글 문자열은 `VARCHAR2(n CHAR)`, 날짜는 `DATE`, 긴 업무 내용과 기타 원문은 `CLOB`을 사용합니다. 날짜 리터럴은 `DATE 'YYYY-MM-DD'`로 NLS 날짜 형식 의존성을 피했습니다.
- `YYYY-MM-DD` 안내문, 전화·이메일의 `-`, 빈 셀은 NULL로 처리했습니다. 자격증·교육·빈 프로젝트 행은 적재하지 않습니다. 학력과 자격증, 교육과 보유능력이 같은 표에 있어도 독립적인 항목으로 분리했습니다.
- 원문의 `OOO`, `OOOOO`, `OOOOOO`, `OOO고등학교`, `OO대학교`, `XXX공학과`는 그대로 보존했습니다. 성명도 원문 그대로 적재했습니다.
- 기본정보의 소속회사·입사일·직위가 공란이므로 경력에서 채우지 않았습니다. 작성자란의 반복 안내 문구도 이름으로 적재하지 않았습니다.
- `2024.10.28 ~ 재직중`은 시작일 `2024-10-28`, 종료일 NULL, `IS_CURRENT='Y'`로 저장합니다. 이는 문서에 기록된 상태이며 현재 재직 사실을 새로 확인한 것이 아닙니다. 종료일 미상인 과거 경력은 `N`과 NULL로 구분해 저장할 수 있습니다.
- 숙련도는 AutoCAD=A, CREO=B, SolidWorks=B를 보존합니다. A/B/C의 구체적인 의미는 문서에 없어 임의로 상·중·하를 부여하지 않았습니다. 외국어용 `LANGUAGE` 분류도 허용합니다.
- 프로젝트 3건의 근무회사는 `소닉스`, 경력표 회사명은 익명 표기입니다. 동일 회사라고 추정하여 FK로 연결하지 않았습니다.
- 개발환경의 `CREO, AutoCAD`는 프로젝트별 TOOL 2행으로 분리했습니다. 비어 있는 다른 환경 유형은 행을 만들지 않았습니다. 헤더의 `yyyy.mm` 안내보다 실제 셀에 기재된 일자까지 보존했습니다.
- 기타란의 `CREO, AutoCAD, SolidWorks`는 원문 텍스트로 별도 보존합니다. 기술 검색·숙련도 조회는 `RESUME_SKILL`을 기준으로 사용합니다.
- 각 목록의 `DISPLAY_ORDER`는 양수이며 이력서 내 중복을 금지합니다. 개발환경은 프로젝트·종류 내 순서 중복을 금지합니다. 원문의 최근 프로젝트 하단 배치는 시작일 오름차순 조회로 재현합니다.
- 종료일은 시작일보다 빠를 수 없고, 재직중 경력에는 종료일을 넣을 수 없습니다. 미기재 날짜는 허용합니다. FK가 참조 중인 부모의 삭제는 기본적으로 거부합니다.
- FK 컬럼은 자식 테이블 UNIQUE 인덱스의 선두 컬럼으로 포함되어 있습니다. 프로젝트 시작일 조회용 인덱스를 추가했습니다.

## 검증 상태

원문 표의 내용과 적재값을 대조하고, 객체·컬럼 참조, 날짜 범위, 이름 길이, SQL 구조를 정적으로 점검했습니다. 이 작업 환경에서는 Oracle 접속 정보와 SQL*Plus/SQLcl 실행 도구가 제공되지 않아 **실제 Oracle에서 DDL·DML을 실행하지 않았습니다**. 실행 후 `03_verify.sql`로 8개 테이블의 기대 건수와 핵심 변환 규칙을 확인할 수 있습니다. 건수 또는 확인 조건이 다르면 오류를 발생시킵니다.

구문 기준은 Oracle 공식 문서의 [CREATE TABLE](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/CREATE-TABLE.html), [제약조건](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/constraint.html), [NULL 처리](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/Nulls.html)를 참고했습니다.
